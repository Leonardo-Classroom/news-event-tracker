## 尚未成形的區塊（不強行拆解）

以下三項在規格與 ADR 中仍是方向而非設計，需先做一次小規模設計或調查，才有辦法產出可信的任務：

| 區塊 | 缺什麼 | 建議處理時機 |
|------|--------|-------------|
| **措辭檢查器**（無罪推定 blocking gate） | 「規則 + 小模型」是方向。實際的違規句型分類、規則覆蓋範圍、小模型的角色與門檻皆未定 | Scope 6 開始前先做設計，需先有標註資料才知道規則能覆蓋多少 |
| **事件「重大性」門檻數值** | 規格暫訂 3 家媒體／5 篇／2 天，但無依據 | Scope 3 之後以 `dataset/` 既有語料回測校準 |
| **監察院採集** | 網站結構、是否有 feed、反爬強度皆未調查 | Scope 9 開始前先花半天調查，再決定 adapter 形態 |

> **實作發現**：Playwright 的 sync API 會在呼叫端執行緒建立 asyncio event loop，
> Django 隨即以 `SynchronousOnlyOperation` 拒絕所有同步 ORM 操作——而採集任務
> 正是「渲染完立刻寫資料庫」。解法是把 Playwright 隔離在專用的單一執行緒
> （`ThreadPoolExecutor(max_workers=1)`），而非設 `DJANGO_ALLOW_ASYNC_UNSAFE=1`。

> 已加 large 測試 `test_渲染後可立即操作_Django_ORM` 守住此回歸。

> 僅標題時，逐字相同的通稿與完全無關的文章距離同為 13；補上全文後更糟，

## 建議的執行順序摘要

```
Scope 0（驗證假設，含外部申請）
   ↓  停損點：假設不成立則暫停
Scope 1（文件入庫）→ Scope 2（理解與檢索）
   ↓  風險點：任務 19 召回率
Scope 3（事件建立）→ Scope 4（時間線因果）
   ↓
Scope 5（官方源）
   ↓  核心價值驗收：任務 37
Scope 6（安全閘門）—— 必須完成才能進 Scope 7
   ↓
Scope 7（公開網站）+ Scope 8（基礎建設）—— 可並行
   ↓
Scope 9（其餘官方源）→ Scope 10（主動觸達）
```

**Scope 6 與 Scope 7 的順序不可調換。** 人工審核僅做形式確認，安全閘門是唯一防線；在閘門完成前對外公開涉及具名個人的未定案司法內容，是實質的法律風險。
