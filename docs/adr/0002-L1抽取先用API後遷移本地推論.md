# 2. L1 結構化抽取先用雲端 API，pipeline 穩定後遷移至本地推論

## Status

被 [ADR-0009](0009-全部LLM走DeepSeekAPI並在抽取前做廉價過濾.md) 取代

本地推論遷移並非專案需求，且在實測語料規模下省不到有意義的金額。
`LLMProvider` 抽象層與模型分級的決定由 ADR-0009 延續。

## Context

L1 抽取層需對每份新增 Document 執行 LLM 結構化抽取（日期、人物、機構、公司、案號、法院、審級、罪名、標案編號、事件觸發詞）。這是系統中量體最大的 LLM 用途。

**量體估算**（每日 3000 篇，每篇約 2000 input tokens / 500 output tokens）：

| 方案 | 每日成本 | 每月成本 |
|------|---------|---------|
| DeepSeek V4-Flash API | 6M in × $0.14/M + 1.5M out × $0.28/M ≈ $1.26 | ≈ $38 |
| 本地 4090（Qwen3-14B AWQ + vLLM） | 約 12–15 分鐘運算，電費約 NT$2 | ≈ NT$60 |

單看穩定運轉，每月 $38 並非負擔。但有兩個場景會改變成本結構：

1. **歷史回填。** 既有 `news report/dataset` 已有數萬篇文章，未來納入更多來源後可能達數十萬篇。單次全量回填走 API 是數百美元，且受 rate limit 影響需數日。
2. **Prompt 迭代。** 抽取 schema 或 prompt 變更時需全量重抽。這在 P1 開發期會反覆發生。走 API 時每次迭代都是實際金錢與等待；走本地時只是機器時間。

硬體條件：RTX 4090 24GB VRAM。同一張卡還需承載 embedding 模型（BGE-M3，約 2.5GB），因此本地 LLM 的 VRAM 預算約 20GB，對應 14B 級模型的量化版本，或 32B 的低位元量化。

其他考量：新聞全文送第三方 API 涉及資料外流；本地推論可完全避免。反向而言，本地部署 vLLM 是一個需要持續維護的服務，對單人維運是實質負擔。

### 選項比較

| 選項 | 優點 | 缺點 | 風險 |
|------|------|------|------|
| 全部走雲端 API | 零維運；抽取品質最高（旗艦模型對法律術語理解較好） | 回填與 prompt 迭代成本高且慢；資料外流 | 開發期反覆重抽的隱性成本可能遠超估算；API 變更或漲價無從迴避 |
| 全部走本地推論 | 邊際成本趨近零；資料不外流；回填與迭代不受限 | 需自建並維護 vLLM 服務；小模型對繁中法律術語的抽取品質待驗證 | **在 pipeline 尚未穩定時就投入推論基礎建設，會拖慢核心價值驗證** |
| **先 API、後本地（分階段）** | P0–P1 專注驗證核心價值；本地化在 prompt 已收斂後才進行，一次到位 | 需要一次遷移工作；期間承擔 API 成本 | 遷移時可能發現本地模型品質不足，需回退（緩解：provider 抽象層）|

## Decision

我們將**分階段**處理 L1 抽取的推論位置：

1. **P0–P1 全部走 DeepSeek API**，使用便宜檔（V4-Flash 級）。目標是最快驗證 pipeline 與抽取 schema。
2. **業務程式碼一律透過 `LLMProvider` 抽象層呼叫**，不得直接依賴任何供應商 SDK。抽象層需支援 structured output / JSON schema 約束。
3. **P2 之後、prompt 收斂後，將 L1 遷移至本地 vLLM**（Qwen3-14B 級 AWQ 量化）。遷移前必須以人工標註測試集比較本地與 API 的抽取品質，本地達到 API 的 95% 以上才切換。
4. **L3 事件歸屬判定與 L4 因果推理／敘事生成永遠走 API 旗艦檔。** 這兩者量體小、難度高、直接影響對外品質，不做成本優化。

## Consequences

**變得更容易：**

- P0–P1 的開發速度：不需同時處理推論服務的部署與調校
- Prompt 迭代：在 API 階段迭代快（不需等模型載入），在本地階段迭代便宜
- 供應商風險：`LLMProvider` 抽象層使 DeepSeek 漲價、停服或品質退步都是局部替換

**變得更困難：**

- 需要維護一層抽象，並抵抗「直接呼叫 SDK 比較快」的誘惑
- P2 的遷移是一次明確的工作項，需要建立抽取品質的標註測試集才能驗證——這個測試集本身是額外工作，但無論如何都該有（規格 M4 也需要它）
- 遷移後 4090 需同時服務 vLLM 與 embedding，VRAM 排程需要規劃；若 P4 之後量體上升，可能需要在兩者間取捨

**明確承擔的成本：**

P0–P1 期間，若發生多次全量重抽，API 費用可能達數百美元。這是為了換取開發速度而刻意接受的代價。若實際重抽次數超出預期，應提前執行 P2 的本地化遷移，而非硬撐。
