# 9. 全部 LLM 推論走 DeepSeek API，並在 L1 抽取前做廉價相關性過濾

## Status

Accepted（取代 [ADR-0002](0002-L1抽取先用API後遷移本地推論.md)）

## Context

ADR-0002 決定「P0–P1 走 DeepSeek API，P2 之後將 L1 抽取遷移至本地 vLLM」。

**本地推論從來不是專案需求。** 原始需求明確指定「結合 LLM，接 DS API」。本地遷移是架構階段被引入的成本最佳化提案，不是被要求的功能。專案擁有者在實作階段指出了這一點。

重新檢視 ADR-0002 的論證：它唯一的實質理由是**回填與 prompt 迭代的成本**。以實測的語料規模檢驗這個論證：

**既有語料實測（`news report/dataset/`，共 340,792 篇）**

| 來源 | 篇數 | 與本專案的相關性 |
|------|------|-----------------|
| 聯合新聞網 | 219,176 | 綜合新聞，部分相關 |
| GQ | 39,116 | 時尚，**完全無關** |
| 中時新聞網 | 32,339 | 綜合新聞，部分相關 |
| VOGUE | 31,698 | 時尚，**完全無關** |
| COOL-STYLE | 16,957 | 時尚，**完全無關** |
| 工商時報 | 1,506 | 財經，部分相關 |

全量抽取的 API 成本約 $143（682M input + 170M output，V4-Flash 費率）。ADR-0002 以此數字論證本地化。

> **費率更正（2026-08-30）**：本 ADR 原引用的 V4-Flash 費率
> （$0.14 input / $0.28 output per 1M）取自第三方整理，與官方不符。
> 官方實際費率為：輸入 cache 未命中 $0.44、cache 命中 $0.014、輸出 $1.32
> （皆為尖峰價，離峰折半）。**輸出價格是原估的約 4.7 倍。**
> 修正後：全量抽取約 $500（尖峰）或 $250（離峰）；過濾後的 1.3–3.8 萬篇
> 約 **$23–46（離峰）或 $46–92（尖峰）**，而非原文所寫的 $5–16。
>
> 費率差異不改變本 ADR 的結論——自建並維護 vLLM 服務的成本仍遠超所省金額——
> 但它使兩件事變得重要：**(a)** 批次作業應排在離峰（省一半）；
> **(b)** context caching 的命中率必須被監測，命中與未命中的輸入價差達 31 倍。
> 兩者皆已納入 `apps.llm` 的用量記錄與後台。

**但這個論證的前提是錯的：不該對全部語料做抽取。**

- 時尚類三站共 87,771 篇（26%）與司法案件、政商弊案毫無關聯，可整批排除
- 剩餘 253,021 篇綜合新聞中，涉及司法／檢調／弊案者估計僅 5–15%，即約 1.3–3.8 萬篇
- 對應的回填成本降至約 **$23–46（離峰）**（見上方費率更正）

在這個量級下，自建並維護 vLLM 服務的成本（設定、除錯、VRAM 排程、持續維運）遠超過它節省的金額。

**更重要的是，前置過濾本來就該做，理由與成本無關。** 無關文件若進入系統，會汙染 ADR-0005 的事件偵測叢集——時尚報導之間的語意相似度很高，足以形成密集簇並通過「≥3 家媒體 ≥5 篇跨 ≥2 天」的門檻，產生大量無意義的事件候選，直接衝擊本已吃緊的人工審核量能。

**另需澄清的區分：** 本 ADR 排除的是**本地 LLM 推論**。ADR-0004 的地端 embedding（BGE-M3，約 2.5GB VRAM）不受影響且維持不變——它是一個小型檢索模型而非生成模型，無 API 成本、無需維護推論服務、且避免將全部語料送往第三方。

### 選項比較

| 選項 | 優點 | 缺點 | 風險 |
|------|------|------|------|
| **全部走 API + 前置過濾** | 零推論維運；符合原始需求；過濾本來就必要 | 持續有 API 費用；語料送第三方 | 過濾規則過嚴會漏掉相關文件（緩解：規則從寬，寧可多送） |
| 分階段遷移本地（ADR-0002 原案） | 邊際成本趨近零 | 需維護 vLLM；**並非專案需求**；在正確的語料規模下省不到什麼 | 維運負擔換取數十美元級別的節省，明顯不划算 |
| 全部走 API、不做過濾 | 實作最單純 | 回填 $143；且無關文件汙染事件偵測 | 叢集產生大量雜訊事件，淹沒審核量能 |

## Decision

1. **所有 LLM 推論一律走 DeepSeek API。** 不自建本地推論服務，不規劃遷移。
2. **保留 `LLMProvider` 抽象層。** 理由與成本無關：它讓所有 LLM 相關行為可以用固定回應做 small 測試（見測試策略「接縫 1」），並隔離供應商風險。
3. **模型分級維持不變**：L1 抽取用便宜檔；L3 事件歸屬判定用中檔；L4 因果推理與敘事生成用旗艦檔。
4. **新增硬性要求：L1 抽取前必須經過廉價相關性過濾。** 過濾以規則為之（來源白名單 + 關鍵字／識別碼比對），不使用 LLM。未通過過濾的文件仍入庫保存，但不進行 L1 抽取，也不參與事件偵測。
5. **過濾規則從寬。** 漏掉一篇相關文件的代價（事件時間線缺一塊）高於多送一篇無關文件的代價（幾分錢）。規則應偏向召回而非精確。

## Consequences

**變得更容易：**

- 維運：沒有推論服務要顧，`leo3.10` 環境只需承載 embedding 模型
- 回填與迭代：實際成本降至 $23–46 一輪（離峰），prompt 迭代的預算壓力有限
- 事件偵測品質：無關文件不進入叢集，雜訊事件候選大幅減少，直接緩解審核瓶頸（規格 R8）
- GPU 規劃：4090 只需服務 BGE-M3 的 2.5GB，不存在 VRAM 排程問題
- 符合原始需求，不再有未被要求的元件

**變得更困難：**

- **前置過濾成為新的正確性關鍵點。** 規則過嚴會靜默漏掉相關文件——這種失敗不會報錯，只會讓某個事件的時間線缺一塊。必須以標註測試集量測過濾的**召回率**，並納入持續驗證
- 過濾規則需要隨領域擴張而維護（新增罪名、新機關、新弊案類型）
- 全部語料經第三方 API 處理，資料外流的疑慮無法用本地化迴避。緩解：僅送通過過濾的文件，且新聞本身已是公開內容

**明確承擔的成本：**

穩定運轉期的 API 費用，以及每輪全量重抽的 $23–46（離峰）。這是為了不維護推論服務而付的錢，且金額在可忽略範圍。

**對既有規劃的影響：**

- 規格書的待決問題 Q8（「4090 是否用於跑本地 LLM」）由本 ADR 回答為「否」
- 任務拆解需新增一項「相關性過濾規則與召回率量測」，置於 Scope 2 的 L1 抽取之前
- 測試策略中「ADR-0002 的本地模型與 API 品質比較」不再需要；標註測試集的用途從三項減為兩項，另新增過濾召回率的量測
